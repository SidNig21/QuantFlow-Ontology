Ontology: the road to shipped

Eight stages from six described types to a charter that regenerates the system. Every stage exits on a test a machine can fail — not a review, not a doc.

Phase 0 substrate — done Frontier Stage 1 Rule no stage ships on prose

Two rules that govern the whole road.

1 · A stage is done when its gate goes green, never when it feels right. If you can't state the gate as a command or a question an agent answers, the stage isn't defined yet.

2 · Governance comes last, not first. Descriptions, lint, lifecycle flags, and conformance tests are added to something that already works. Adding them up front is how the last few months happened.

STAGE 1one weekend

Research plane, ungoverned

Six types in one file: Hypothesis, Dataset, Run, Artifact, Evaluation, Report. Each gets a name, a two-sentence description written for an agent to act on, its properties, and its links to the other five. Nothing else — no lint, no lifecycle, no plane structure, no tests.

This plane is invariant in the doctrine, which means there is nothing left to decide. It is pure typing. That's exactly why it goes first: zero open questions removes every excuse.

Exit gateRED
Hand-write fixture rows. Give an agent only this file, then ask:
"Which Runs from Hypothesis X produced Evaluations above threshold Y?"
It answers correctly with no hand-holding, or a description is underspecified.
The trap here

Reaching for structure before content. If you find yourself designing the file format, stop and write the Hypothesis description instead.

STAGE 22–3 days

Bind the plane to the Kernel

Every type gets a real table; the Kernel reads and writes through it. The types stop being a document and become where data actually lives. Reuse the existing conformance machinery rather than rebuilding it.

Exit gateRED
A live Hermes seat completes one real task, and the resulting Run and Artifact rows exist in the Kernel — queryable, not narrated.
STAGE 3~1 week

Generated tool plane · two gates

Tools are generated from the types, not hand-written. Each generated action tool is one dumb tool wrapped in two checks — the Coyle spec, made concrete:

  • Gate 1 · input — Zod validation of the call's shape at execute. This closes the exact hole the Cursor audit flagged.
  • Gate 2 · output — the transition-table / ontology check on the result. You already built this machinery in WO-005.
Exit gateRED
A malformed call is rejected at Gate 1 before touching the Kernel. An illegal state transition is rejected at Gate 2 before it commits. Both failures are proven, not assumed.
The trap here

Generating tools for types you haven't proven readable in Stage 1. Bad descriptions produce bad tools silently.

STAGE 4~1 week

Market plane, derived empirically

Do not design Venue / Instrument / Quote / MarketEvent from principles. Load one real market's data and let it force the shape. Then load a structurally different one — a game line and a perp, say — and keep only what survives both.

This is where betting stops being types and becomes rows. It is the move that makes "a market of his choosing" a real claim rather than a slogan.

Exit gateRED
Two structurally different markets load into the same four types with zero new object types added. If either needs a special type, the abstraction failed — fix it now, not later.
STAGE 52–3 days

Agent plane

Seats, sessions, tasks, and peer messages become described types like everything else. Most of these rows already exist in the Kernel — this stage is mostly recognition and description, not construction.

Exit gateRED
An agent answers a cross-plane question — "which seat produced the Run behind this Report" — from the ontology alone.
STAGE 62 days

Now add governance

Only now: description-required lint, lifecycle flags (experimental → active), extend-don't-mutate, and the anti-pattern gates. Each is roughly an hour, applied to a system that already works. This is the doctrine's Phase 1 arriving last on purpose.

Exit gateRED
CI goes red on each of three deliberate sabotages: a missing description, a Run subtype clone, and a property removed from an active type.
STAGE 7~1 week

The regeneration proof

The charter earns its name only if the system is downstream of it. Change one type in the ontology and everything derived — tables, tools, typed access — regenerates without hand-editing.

Exit gateRED
Add one property to Evaluation, run codegen, and the new property is callable end to end with zero files edited by hand.
Why this stage matters most

Until regeneration works, the ontology is documentation. After it works, it is the constitution — and that's the actual difference between a schema and a charter.

STAGE 8later, on evidence

Recall layer

Hybrid retrieval over accumulated Runs, Evaluations, and Reports so an agent can ask whether something like this has been tried before. In-Kernel first — stay on the existing substrate rather than standing up a second database and a second service.

Build this when the history is big enough to be worth searching, not before. Same rule applies to swapping the execution substrate: migrate on a failure, never on aesthetics.

Exit gateRED
An agent retrieves a prior Run relevant to a new Hypothesis that keyword search alone would have missed.
DONEthe only definition that counts

Definition of done

A market you choose on the day is loaded into the Market plane without new types. A Hypothesis is stated, a Run executes against a fenced Dataset, an Evaluation scores it, a Report is produced — and every object in that chain was reachable through generated tools an agent used unaided.

Everything on this page exists to make that one sentence true. Nothing else is progress.
