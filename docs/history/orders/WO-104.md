# WO-104 — The read plane: make the generated read tools real, and serve them (doctrine P3, rung 1 of 3)

status: open
assignee: builder
depends: WO-103b (done, merged `99a41c7`)

## Objective

Give the Kernel a schema-driven read layer, add the missing link-traversal tool, and serve the
generated **read** tools over MCP — with zero action tools served, so the observe door stays shut
for one more rung.

## In plain terms

The system already publishes a list of 71 things an AI could ask it — and not one of them works.
This rung makes the *reading* half real: an AI can finally look up a record, search records, and
follow the connections between them. It still cannot change anything.

## Read this before you scope your work — the rung is split three ways

`SCOPES.md` P3 is "the generated tool plane," flagged as the fattest rung on the ladder. It is
**split before the build, not during it** (WO-103 was split for size and still took two rework
rounds; that lesson is what this split is for):

| Rung | Scope | Why the boundary is here |
|---|---|---|
| **WO-104 — this order** | Read tools: `_get`, `_query`, `_links`. Served over MCP. **No action tools.** | Reading cannot fabricate a record. The whole rung is safe by construction |
| WO-105 | Action tools + GATE 1 (Zod-parse at `execute()`) + GATE 2 (transition check) | This is where writes get served, so **this is where the `qf_observe_ticket` serving decision lands** |
| WO-106 | Cold seat calls generated tools; hand-grown `qf_*` verbs retire | Needs both halves served first |

**The boundary is load-bearing, not tidiness.** `observe_ticket` is an *action*. Serving only read
tools means WO-104 cannot open the door ROADMAP debt #22 names, so that decision is made in the
rung that actually forces it instead of by a code generator nobody is reading. **Do not serve a
single action tool in this order**, and do not "prepare" for them in a way that would serve one by
default.

## Deliverable 1 · A schema-driven read layer in the Kernel

Three functions, **type-agnostic** — they take the type name as data and derive everything else
from the schema. No `switch`, no per-type branch, no hand-written function per object type.

- **`getObject(db, type, id)`** → one row or null.
- **`queryObjects(db, type, filters?, limit?, offset?)`** → rows. **Filter semantics are pinned, not
  yours to choose** *(added at the pre-build read)*: **equality only, combined with AND, over
  declared properties only.** No ranges, no operators, no OR. Anything richer is a later rung — say
  so if you think it is needed, do not add it.
- **`getLinks(db, id, opts?)`** → link rows touching that id, in either direction, optionally
  filtered by `kind`. **This is the first production reader the `links` table has ever had.**

**Hard constraints:**

- **Reject unknown type names** before touching SQL. A type name that is not in the schema must
  error, not interpolate. This is the injection seam; treat it as one.
- **Reject unknown filter keys** the same way, for the same reason.
- The four existing hand-written readers (`listArtifacts`, `listAgentSessions`,
  `listAgentDefinitions`, `getAgentDefinition`) **stay** — `collab-electron` calls them and this
  order does not touch the app. Say in your report whether they should later become callers of the
  generic layer; **do not** change them here.
- Reads go through the Kernel package. This is not a `kernel-sole-writer` question (nothing writes),
  but the read path belongs beside the write path, not in the server.

**Known trap, declared:** `stateFieldName`'s `status|grade` heuristic (ROADMAP debt #4) fans into
four consumers. If your generic layer needs the state field and the heuristic gives a wrong answer
for any type, **stop and report it** — do not add a fifth consumer of a heuristic that is already
logged as debt.

## Deliverable 2 · The missing third read tool

`generateMcp()` emits `_get` and `_query` per object (`src/generate/mcp.ts:34-50`). Doctrine P3
calls for **get / search / traverse-links**. The third does not exist.

Add **`qf_<object>_links`** per object type, generated the same way — input is an id plus an
optional `kind` filter, described from the schema.

**Also fix a lie the generator already ships** *(found at the pre-build read).* `_query`'s
description says "List `<object>` rows **with optional filters**," but `queryInput`
(`src/generate/mcp.ts:25-28`) accepts only `limit` and `offset` — there are no filters. Deliverable
1 adds real filtering to the Kernel, so without this the capability exists and **no tool can reach
it**, which is doctrine A5 reintroduced by the rung that is supposed to close it.

**Ruling: `_query`'s generated `inputSchema` must expose each declared property as an optional
equality filter,** derived from the object's own Zod shape alongside `limit`/`offset`. The
description then becomes true. If a property type cannot be expressed in the JSON-Schema conversion,
**omit that property and name it in your report** — do not silently narrow the description again.

## Deliverable 3 · The MCP read server — read tools only

A server that registers the **69 read tools** and nothing else, backed by deliverable 1.

- **Serve zero action tools.** Not disabled, not registered-and-rejecting — **absent from the
  served list.**
- **The exclusion mechanism is named, not left to you** *(added at the pre-build read: "schema-driven"
  and "zero actions" are jointly satisfiable three different ways — iterate objects only, filter
  `tools.json`, or add a read-only generator flag — and the first draft named none of them, so two
  honest builders would have shipped different servers).* **Register by iterating `schema.objects`
  and emitting exactly three tools per object. Never touch `schema.actions`. Never read
  `golden/tools.json` at runtime.** Actions are excluded because they are never visited, not
  because they are filtered out afterward.
- Registration is therefore **driven by the schema**: a new object type yields its three tools with
  no new hand-written tool code. That property is the doctrine phase-exit gate (G2) — build for it.
  **No per-tool name literal outside that loop.**
- Follow `tools/qf-peer-bus/src/server.ts` for stack shape. Its own package is the precedent for
  where a tool server lives; state where you put yours and why.
- The server opens the Kernel read-only where the driver allows it. If it cannot, say so with the
  measurement rather than assuming.
