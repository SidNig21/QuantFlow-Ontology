## Objective

Adjudicate every declared-but-unexecutable action, collapse the second link store, resolve the
schema doc that describes a dead schema, and gate the one door that is about to open by itself —
all before WO-104 turns the action surface into a published tool surface.

## In plain terms

The system currently advertises six things it cannot do, and the next rung turns every advertised
thing into a button an AI can press. This order removes the six lies before they become buttons,
and adds an alarm on one door we know is unlocked.

## Why this rung is now and not later — the mechanism

WO-104 builds the generated tool plane. The generator emits **one tool per action** plus
`_get`/`_query` per object. Measured on `main` at `aeee874`:

```
77 tools = 23 objects × 2 (_get, _query) = 46,  plus  31 actions × 1 = 31
```

Verify it yourself before you start; a count you did not derive is a count you cannot defend:

```bash
bun -e 'const t=JSON.parse(await Bun.file("qf-kernel-schema/golden/tools.json").text());
const g=t.filter(x=>x.name.endsWith("_get")).length, q=t.filter(x=>x.name.endsWith("_query")).length;
console.log("total",t.length,"_get",g,"_query",q,"action-tools",t.length-g-q)'
```

So every dead action shipped into WO-104 becomes **a published tool that throws `Unknown command`
at `execute()`**. And `qf_observe_ticket` — the door ROADMAP debt #22 exists for — is *already
generated*, at `golden/tools.json:1060`. It is not served yet: nothing reads `tools.json` at
runtime and there are zero `ListTools` handlers repo-wide (both verified 2026-07-26). The door
opens on WO-104 **by codegen, with nobody making a decision**. That is what this rung interrupts.

**Read that last line carefully.** `has_leg` is `ticket → instrument`. It is the link that records

**Counting rule (inherited from WO-103, still binding).** A link kind counts as writable only if at
least one legal `(from, to)` pair has both endpoints creatable through `execute()`. Union endpoints
count if *any* member qualifies — that is why `tests` (`run|strategy → hypothesis`) is writable via
`run` though `strategy` has no verb. Report only end-to-end writable kinds; list the rest with the
blocker named. **A capability count that includes unreachable capabilities is the failure doctrine
A5 names.**

## Deliverable 2 · The `connection` ruling — one store, not two

Measured: `connection` carries exactly `{ kind, from_ref, to_ref }`, lifecycle `experimental`.
That is **a link stored as an object**, duplicating the `links` table WO-103 made writable. Two
mechanisms for one job is a soft breach of the One Rule.

The founder's cable use case is the real argument on the other side — dragging a tile to a browser
tile draws a visible cable, and a cable may be a *canvas gesture* rather than an ontology edge (the
cable principle, `SCOPES.md`). So this is a decision, not a cleanup.

**Decide it and state which:**

- **(a)** `connection` is canvas-only presentation → then it must not carry ontology semantics.
  Strip `kind`/`from_ref`/`to_ref` down to what the canvas actually needs, or move it out of the
  ontology entirely. Say which and why.
- **(b)** `connection` is a real edge → then it is redundant with `links` and goes; the canvas
  reads `links`.

Whichever you choose, the report states **what a cable is** in one plain sentence. That sentence is
the deliverable; the diff is downstream of it.

## Deliverable 4 · The `observe-door` gate — debt #22's check becomes a duty

ROADMAP debt #22 records that `observe_ticket` may be called by anything, and its check is a grep
somebody has to remember to run. **Three separate seats hand-wrote three triggers for this entry
on 2026-07-26 and all three read "safe" while exposed** (see Known findings). A trigger is a
document; documents rot. Make it a gate.

Add gate **`observe-door`** to `qa/run.ts`, using the `bunPackageGate` conventions WO-H1 extracted.
It asserts **two** things, and it must be red if either fails:

1. **The string surface.** `observe_ticket` / `qf_observe_ticket` appears only in this committed
   allowlist — measured today, code and generated artifacts only:
   ```
   qf-kernel-schema/src/ontology/research.ts   (definition)
   qf-kernel-schema/src/commands.ts            (command wiring)
   qf-kernel-schema/src/schema.ts              (aggregator)
   packages/qf-kernel/src/create.ts            (implementation)
   packages/qf-kernel/src/kernel.test.ts       (tests)
   qf-kernel-schema/golden/{ONTOLOGY.md,migration.sql,tools.json}  (generated)
   ```
   Any occurrence outside it — a `collab-electron` callsite, a `tools/` caller, an entry in
   `QF_EXECUTE_ALLOWLIST` — is **red**. Documentation paths are excluded; prose is not a call.

2. **The serving surface.** Nothing outside `qf-kernel-schema/` reads `golden/tools.json` at
   runtime. Verified today: the only readers are `scripts/generate.ts` (writes it) and
   `generate.test.ts` (diffs it). **This clause is the one that catches WO-104**, because a
   generic MCP server that serves every tool in the file opens the observe door without the string
   `observe_ticket` appearing anywhere in the new code.

**State the gate's limit in your report, plainly.** It does not prevent serving `observe_ticket`.
It prevents serving it *silently* — WO-104 will have to touch this gate, which forces the decision
into the open where a human sees it. A gate that is honest about what it does not cover is worth
more than one that implies coverage it lacks (WO-103's verification record set this precedent).

Then update ROADMAP debt #22: replace its inline grep with a pointer to this gate. Leave the entry's
prose and trigger otherwise intact — it is the founder's wording.

## Deliverable 5 · Two rulings recorded, zero machinery built

**(a) The market-plane ingest seam — architect's ruling, record it.**

The contradiction: `instrument` and `quote` are `pipelineFed`, so `lintCommands` rejects creation
commands for them *by design* (`define.ts:535`). WO-107 says their rows "land through Kernel
commands." Both cannot be true, and 4 unwritable link kinds — including `has_leg` — sit on it.

**Ruling: `pipelineFed` stays. Ingest goes through `execute()` via a dedicated bulk command that
carries an ingest trace.** Reasons, both load-bearing:

- `kernel-sole-writer` is a hard law. An ingest path that bypasses `execute()` fails it, correctly.
- Dropping `pipelineFed` would let any caller hand-author a `quote` — a fabricated price. That is
  debt #22's fabrication risk one plane over, and it would be introduced *while* we are closing the
  first one.

**Your job is to record this, not build it:** a SCOPES contract for the ingest rung (objective ·
depends · in · out · gate) and a ROADMAP line noting the 4 link kinds it unblocks. If you find a
measurement that contradicts either reason, stop and say so.

**(b) The IPC allowlist — state the decision, change nothing.**

`QF_EXECUTE_ALLOWLIST` is one command wide (`publish_artifact`), enforced only at the renderer→main
IPC boundary (`ipc-kernel.ts:110`). Main-process callers reach `kernelExecute` unfiltered. That is
defensible as a trust tier — the renderer is untrusted, the main process is ours — but it is
currently an accident with a plausible story attached, not a decision.

Write the decision into `SCOPES.md` in one paragraph: what the tier is, why the boundary is where
it is, and what would have to be true to add a second command. **Do not change the allowlist.**
Adding to it is now debt #22's own trigger.
