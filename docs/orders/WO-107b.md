## Objective

Land pipeline-fed `instrument` and `quote` rows through one atomic, replay-safe Kernel command with
durable source provenance. This order builds the trustworthy pipe; WO-107 connects real Bovada data.

## In plain terms

QuantFlow has market-shaped tables but no honest way to fill them. Build one door that can load a
batch completely or not at all, remembers where every row came from, and cannot quietly become a
second agent-facing write surface.

**If it goes wrong:** a partial price batch becomes permanent truth, a retry duplicates evidence,
an old founder database stops opening, or callers bypass `execute()` and create a second ledger.

## Measurements that bind this order

Re-measured against `main` at `d5886de` before cutting the order:

- the schema declares 23 objects and 25 actions; `instrument` and `quote` are `pipelineFed`, but
  there is no ingest action or runtime handler;
- `execute(db, "ingest_market_batch", ...)` throws `Unknown command` and writes no rows/events;
- `quotes` is unreachable until both market rows can exist; `has_leg` is reachable only after an
  instrument exists, through the already-shipped generic link writer;
- `execute()` dispatches only the transition and creation catalogs. A pipeline action placed in
  either catalog would lie: creation owns one object type and `lintCommands` correctly rejects
  creation/transition verbs for `pipelineFed` objects;
- adding one schema action changes `schema_meta`. The founder's pre-D1 shape and the current D1
  shape therefore both require an explicit generated `0002` upgrade path;
- `qf-kernel` publicly exports `creationHandlers`, `appendEvent`, and `insertRun` from both package
  entries. No production caller needs those write primitives, but the current sole-writer gate
  exempts the package that exposes them;
- `.strict()` currently protects only the command envelope. Declared JSON records such as
  `instrument.params` and `quote.coverage` intentionally remain open JSON.

These are repository measurements, not inherited audit conclusions.

## RULING 1 — a third command family, not a special-case name

Add `pipelineOnly?: boolean` to action metadata and add one schema-owned `pipelineCommands`
catalog beside transitions and creations. `ingest_market_batch` is the first member.

The lints must prove set equality across all three catalogs, require every pipeline command to name
only `pipelineFed` object types, require its action to be `pipelineOnly: true`, and reject actions
that are both `operatorOnly` and `pipelineOnly`. `execute()` dispatches from the catalog; it must not
contain `if (command === "ingest_market_batch")` as an ungoverned fourth map.

`pipelineOnly` actions are generated into the complete ontology/tool authority but excluded from
the served MCP action set, exactly as `operatorOnly` is excluded for a different reason. A Dock
agent may read the resulting rows; a trusted pipeline invokes the command through `execute()`.

## RULING 2 — strict batch, declared open payloads

The action input is one strict batch envelope:

```text
source_artifact_id   existing Artifact that identifies the captured source
observed_at          valid ISO-8601 timestamp for this observation batch
instruments[]        strict rows: id, kind, params, sides, correlation_group
quotes[]             strict rows: id, instrument_id, book, data_ref, coverage
```

At least one row is required. Duplicate object IDs inside a request are rejected before writing.
`instrument_id` is the only quote-edge declaration; the Kernel derives exactly one `quotes` link
for each quote. Do not accept a free-form links array.

Unknown keys on the batch, instrument row, and quote row are rejected rather than stripped.
`params` and `coverage` remain explicitly declared open JSON escape hatches; do not claim nested
strictness for them and do not interpret their contents in this order. `sides` retains the schema's
declared JSON-array contract. This records, rather than conceals, ROADMAP debt #26.

## RULING 3 — one transaction, deterministic retry

Validate the entire request, source Artifact, duplicate IDs, foreign keys, and canonical row
digests before committing. Then one outer `KernelDb.transaction()` owns all object rows, derived
`quotes` links, and events.

For every ingested row, append exactly one event whose payload carries:

```text
command · source_artifact_id · observed_at · row_digest · span_id
```

The event's existing `trace_id` is the shared ingest trace. `row_digest` is computed inside the
Kernel from a documented stable canonical serialization of the stored domain fields; caller input
cannot choose it. Created-at timestamps are not digest inputs.

Retry rules are exact:

- same IDs + same canonical row state + same source/provenance + same derived link: no-op, with no
  duplicate row, link, or event;
- an existing ID with different state or provenance: typed conflict and zero writes from the batch;
- any failure, including the last row: zero rows, links, and events from the batch.

Do not implement silent upsert or last-write-wins prices.

## RULING 4 — upgrades are part of the feature

Generate and commit `golden/upgrades/0002-market-ingest.sql`; never edit `0001`. The runtime must
classify exact predecessor shapes and apply a data-preserving chain:

```text
pre-D1 founder shape → 0001 → 0002 → current
D1 / WO-N1 shape     → 0002        → current
fresh database                        current
```

Partial, damaged, or unknown shapes still fail closed for writers. The real Linux `app.asar` must
contain every upgrade authority the runtime resolves. Existing rows/events/links survive byte-for-
byte except for the one new `schema_meta` action row.

## RULING 5 — close the public write bypass while this boundary is open

Remove production package exports for `creationHandlers`, `appendEvent`, and `insertRun` from both
`.` and `./portable`. Internal implementation/tests may import their source modules directly.
`execute()` remains the only public domain-write API.

Add a structural gate over the package exports and production dispatch surface. `kernel-sole-writer`
cannot prove this by itself because it deliberately trusts the Kernel package.

## RULING 6 — links: own only what this order can make truthful

- `quotes`: created by the ingest transaction from each strict quote's `instrument_id`.
- `has_leg`: prove reachability using the existing generic link command after ingest creates an
  instrument and a fixture creates a ticket. Do not read, reconcile, or infer `ticket.legs`.
- `offered_on` and `lists`: remain blocked until `market_event` and `venue` creation arrives in
  WO-107. Do not manufacture those verbs here.

## Deliverables

### D0 — one public write door

Remove the three public write primitive exports from both package entries. Add the exact export /
dispatch inventory gate and update internal tests without weakening their assertions.

### D1 — honest pipeline action

Add `pipelineOnly`, `PipelineCommand`, `pipelineCommands`, the schema action, coupled lints, generated
surfaces, and `execute()` catalog dispatch. The action is generated but never served over MCP.

### D2 — upgrade chain

Ship generated `0002`, predecessor/current classification, transactional upgrade chaining, fresh
and historical fixtures, and package resolution/inspection for the new authority.

### D3 — atomic market ingest

Implement the RULING 2/3 contract for `instrument` + `quote`, including source Artifact validation,
canonical digests, row-event bijection, derived `quotes` links, replay no-op, typed conflict, and
whole-batch rollback.

### D4 — end-to-end reachability

Prove generated reads answer over ingested instrument/quote rows and the derived `quotes` edge.
Prove `has_leg` becomes creatable through the existing link command without claiming `ticket.legs`
authority. Keep `offered_on`/`lists` honestly blocked.

### D5 — permanent `market-ingest` gate and current docs

Add one gate that covers D0–D4 and register it with the QA runner. Update the root README's pipeline
statement: pipeline-fed types have no per-type/manual agent verbs; trusted bulk commands still pass
through `execute()`. Regenerate all schema golden outputs; conformance output should remain unchanged
unless the builder reports and justifies otherwise.

## Required falsification

Four baits, each red → restore → green:

1. Re-export one raw write primitive from a production package entry.
2. Remove `0002` from one historical upgrade path or from the real packaged app.
3. Remove `pipelineOnly` from the action so it becomes serveable or catalog-incoherent.
4. Break the outer transaction (or commit a first row before a deliberately invalid final row).
