# WO-107c — Market context completes the ingest graph

status: **open — current after WO-107b PASS.**
assignee: —
depends: WO-102 + WO-103 + WO-107b
blocks: WO-107 (real Bovada football capture)

## Objective

Give trusted ingestion an idempotent way to establish one venue and scheduled market events, then
atomically attach every ingested instrument to its venue and optional bounded event.

## In plain terms

Prices can now enter QuantFlow safely, but they still cannot say where they were offered or which
football event they belong to; complete that graph before connecting live Bovada football data.

**If it goes wrong:** the founder sees prices detached from Bovada or from their event, retries
duplicate context, an agent can fabricate source facts, or another schema upgrade strands an old
Kernel.

## RULING 1 — context uses trusted creation commands

Add exactly two schema actions and creation commands:

```text
register_venue         → venue.registered
schedule_market_event  → market_event.scheduled
```

Both actions are `operatorOnly: true`, generated into complete authority, and absent from every
agent MCP serving/advertising path. They still enter through public `execute()`; do not export a
handler or create a pipeline side door.

Neither context action accepts the Kernel creation envelope. Calls containing `links` or `bytes`
must be rejected before any write; the handlers receive no caller-supplied links. Their only
successful writes are the named context row and its one provenance event. A handler-level reusable
rejection is acceptable; do not add a command-name special case to `execute()`.

`register_venue` accepts a stable `venue_id`, `kind`, `name`, existing `source_artifact_id`, and
valid `observed_at`. `schedule_market_event` accepts a stable `market_event_id`, `sport`,
`starts_at`, `competition`, existing `source_artifact_id`, and valid `observed_at`. It does not
accept `status`; the Kernel writes `scheduled`.

Both commands are exact-replay safe: same identity, stored state, source Artifact, observation
time, and trace returns a replay receipt without another row or event. Any disagreement is a typed
conflict and writes nothing. Do not silently update renamed venues, rescheduled events, or changed
competition text in this order; future reconciliation must be its own governed action.

Both paths return exactly:

```text
ContextExecuteResult {
  kind: "context"
  command: "register_venue" | "schedule_market_event"
  object_type: "venue" | "market_event"
  object_id
  source_artifact_id
  trace_id
  row_digest
  outcome: "created" | "replayed"
  state
}
```

`ExecuteResult` and literal `ExecuteResultFor<C>` include that discriminant; a replay must say
`outcome: "replayed"`. A disagreement throws `MarketContextConflictError` carrying
`object_type: "venue" | "market_event"`, `object_id`, and `reason`.

Canonical digest inputs are exactly venue `{id,kind,name}` and market event
`{id,sport,starts_at,status:"scheduled",competition}`. Source Artifact, observation time, trace,
span, and `created_at` are provenance checked separately and are not digest inputs.

Every newly created context row has exactly one provenance event carrying
`command · source_artifact_id · observed_at · row_digest · span_id`, with the event's existing
`trace_id` as the shared trace. Compute the stable digest from stored domain fields only.

## RULING 2 — extend the existing batch; do not add another ingest command

Extend the strict `ingest_market_batch` input:

```text
venue_id                       existing venue for every instrument in this batch
instruments[].market_event_id  existing event identity or null
```

`market_event_id: null` preserves doctrine A7's cheap hedge: an instrument has no mandatory event
dependency. For the bounded Bovada football shapes WO-107 will ingest, it is non-null.

The existing outer transaction must validate context before writing and derive:

- exactly one `lists` edge `venue → instrument` for every instrument;
- exactly one `offered_on` edge `instrument → market_event` when `market_event_id` is non-null;
- the already-shipped `quotes` edge `quote → instrument` for every quote.

Exact replay checks all declared edges. Missing context, a different venue/event edge, duplicate
edge, or a failure on the last edge rolls back the whole batch: no new market row, link, or event.
Do not infer context from `params`, `coverage`, names, or caller-supplied free-form links.

## RULING 3 — `0003` is one finite, fail-closed history step

Generate and commit `golden/upgrades/0003-market-context.sql`; never edit `0001` or `0002`. The
runtime must classify and preserve the exact supported ladder inside one upgrade transaction:

```text
pre-D1 founder shape → 0001 → 0002 → 0003 → current
D1 shape            → 0002 → 0003        → current
WO-107b shape       → 0003               → current

```

The package resolver and real Linux inspector must require and byte-compare `0003`. The structural
identity gate must name the exact three literal upgrade files under the writable branch and reject
dynamic or extra authorities. Unknown/damaged shapes remain read-only-warn or writer-fail-closed
according to the existing Kernel contract.

1. Make either trusted context action agent-serveable.
2. Remove `0003` from one runtime predecessor path or the real packaged app.
3. Accept caller-supplied non-`scheduled` initial event status or make an exact replay append a
   second provenance event.
4. Wrap a real `KernelDb` with a driver seam that throws on the final `INSERT INTO links` for a
   valid `offered_on` edge, after at least one new instrument row, event, and `lists` edge have
   executed; assert zero new rows, links, and events. A preflight-invalid context reference does
   not satisfy this bait.
