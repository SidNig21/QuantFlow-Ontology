## In plain terms

Right now the system can describe 23 kinds of thing but can only bring **three** of them into
existence, and it cannot record a single relationship between any two — the table for connections
exists and has never been written to. This order builds the write path: the missing stages of your
research workflow become creatable, and the graph gets edges. It also fixes a live break: renaming
the market types last rung silently killed the Kernel's ability to run them.

**If it goes wrong:** the ontology stays a filing system with no filing — every rung above this one
would be building tools that read empty tables and a loop that cannot record itself.

## This rung is split. Read why before you scope your work.

The SCOPES contract for WO-103 lists creation, edges, arrival-settled objects, market ingest,
the adjudication of nine dead actions, and an IPC allowlist decision. **That is two orders.** The
seam is mechanism versus policy:

- **WO-103 (this order): the mechanism.** Rows can be created, edges can be written, and the
  six-stage chain runs end to end. Wires three of the nine dead actions because they *are* the
  workflow.
- **WO-103b (contracted in `SCOPES.md`, written after this reports): the policy.** Adjudicating
  the remaining six dead actions, the `ONTOLOGY_SCHEMA.md` surface those deletions force

**Why this seam and not another:** deleting an action changes the *action surface*, which trips
`qa/gates/doc-action-surface.ts` and drags `docs/ONTOLOGY_SCHEMA.md` in with it. **Wiring** an
existing action changes no names and trips nothing. So this order can wire freely and touches no
docs; WO-103b owns every deletion and the doc surface in one coherent diff.

## Deliverable 0 · The Kernel is broken. Fix it first, and gate it.

**Measured, reproduced, and confirmed at runtime.** `execute.ts:13` and `execute.ts:21` hardcode
the stateful types:

```ts
const ID_FIELD:    Record<TransitionCommand["type"], string>              = { …, event: "event_id",  … };
const STATE_FIELD: Record<TransitionCommand["type"], "status" | "grade">  = { …, event: "status",    … };
```

WO-102 renamed that type to `market_event`. **`event` is no longer a valid key and `market_event`
is absent from both maps**, so all three market commands are dead. Reproduced on a fresh database:

```
seeded: {"id":"me1","status":"scheduled"}
THREW: KernelError | Command "start_event" requires undefined
```

`ID_FIELD["market_event"]` is `undefined`, so `objectId()` reads `input[undefined]` and throws.
`readState()` would then build `SELECT undefined AS state FROM market_event`.

**Why nothing caught it, which is the more important half.** `packages/qf-kernel/package.json`
declares a `typecheck` script (`bunx tsc --noEmit`) that **no gate has ever run** — zero
occurrences of `tsc`, `typecheck` or `noEmit` in `qa/run.ts`. Run by hand it names both lines
exactly:

```

  'Record<"run" | "hypothesis" | "ticket" | "market_event" | "agent_session", string>'
```

A capability that exists and is never invoked is the failure doctrine A5 names. WO-102's builder
followed its order correctly — the order's escape clause said *"if a Kernel change is required,
stop and report"*, and the requirement was invisible without a typecheck. The verifier confirmed
"zero Kernel files touched" as a virtue and did not ask whether the Kernel still worked.

**Do:**

## Deliverable 2 · Link writes — the generic endpoint-validated writer

**This is the order's centrepiece.** `execute.ts` branches exactly two ways today — creation
(`:111`) and transition — with no link branch. The `links` table has been generated and
CHECK-constrained since WO-001 and has **never been written to**.

**Ruling (architect, adopted from the WO-102 verifier's proposal and already recorded in
`SCOPES.md`): layer the two options, do not choose between them.**

- Creation input accepts **optional link fields**.
- They are implemented internally by **one generic link writer**.
- That writer validates every edge against the schema's **already-declared endpoints** —
  `evaluated_by` declares `[artifact,run] → [evaluation]`, `derived_from` declares
  `[dataset,artifact,strategy] → [dataset,artifact,strategy]`, and all 14 links carry the same
  declarations.

**Why, so you do not relitigate it mid-build:** it keeps **write-path singularity** (Law B) — one
writer, not a second verb. It makes an edge **atomic with its node**, so a run never exists, even
momentarily, unattached to its hypothesis. It is **generatable**, which is what matters at WO-104:
one traversal tool over declared endpoints instead of a per-type shape that churns whenever a link
is added. And it is the pattern `execute()` **already uses** — generated transition tables
validating transitions — applied to generated endpoint tables validating edges. Nothing new is
invented.

**The endpoint validator is the deliverable; the link-writing convenience is not.** An edge whose
`from` object is the wrong type must be rejected *before* commit, by data, never by a hand-written
`if`.

## Deliverable 4 · Objects that arrive already settled (doctrine A6, the founder's first use case)

The founder supplies a **real betting slip that is already won or lost.** Today `ticket` is
`pending → win|loss|push|void`, so the only available path is to create it `pending` and
immediately transition — **writing into the event log a state the ticket was never in.** That is a
fabricated fact in the ledger the whole design exists to keep honest.

Add `ticket` creation that can accept a **terminal grade on arrival**, with this constraint, which
is the sharpest design call in the order:

> **An externally-observed fact may arrive in any state. A system-produced object may not.**

The distinction must be **structural and machine-enforced**, not a comment — an agent must not be
able to fabricate arbitrary states for objects it generated itself.

**Amended 2026-07-25 (round-1 rework, founder ruling). `ticket.origin` as an input field is
insufficient, and the mechanism is now decided — do not relitigate it.**

Round 1 gated on `origin` (`strategy_proposed | operator_supplied`) read straight off the command
input. Measured through the real `execute()` by the checking seat:

```
create_ticket + origin=strategy_proposed + grade=win  → rejected (FabricatedStateError)
create_ticket + origin=operator_supplied  + grade=win  → ACCEPTED, row written at grade=win,
                                                          event ticket.observed
```

Same caller, same grade, **one relabelled field**. A self-declared provenance flag is a comment
with a type, which is exactly what this deliverable forbids.

**The ruling: split the verb.**

- **`create_ticket`** — system-produced. **Does not accept a grade at all.** Always starts
  `pending`. Supplying a grade is rejected, not silently coerced.
- **`observe_ticket`** — externally ingested. **May arrive at any legal grade**, terminal included.
  Writes an *observation* event, never a synthetic transition.
- **`ticket.origin` is derived from which verb was used and is no longer accepted as input.**
  There is no field left to relabel.

**Why the verb and not the field:** the command surface is a structure an agent cannot edit from
inside a call, and it is the seam WO-104's generated tool plane needs — `observe_*` verbs can be
withheld from strategy agents at the tool boundary, which a field can never be.

**State the residual honestly in your report, because it is real:** no in-Kernel mechanism can
stop a caller that invokes `observe_ticket` for something it produced itself. Only caller identity
in `TraceContext` — which does not exist today — closes that, and it is not this order's job. What
the verb split buys is that the lie becomes a **recorded, auditable act in the event log** rather
than an invisible field value, and the accidental path disappears entirely. Do not overclaim this
as airtight.

The event log must record what actually happened — an *observation* at a known state — never a
synthetic transition from a state that never existed.

**This generalizes past `ticket` to every object ingested from the outside world**, so design it as
a property of the creation path, not a `ticket` special case.

**Round 1 claimed this generalization and did not deliver it** — `TERMINAL_TICKET_GRADES`
(`create.ts:23`), the rejection (`:589`) and the observation event (`:593`) all live inside
`createTicket`, with no shared mechanism; meanwhile `create_run` silently coerced a supplied
`status: "succeeded"` to `queued` rather than rejecting it. The create/observe split must be a
**named, reusable property of the creation path** that a second ingested type can adopt without
copying code, and **silent coercion of a caller-supplied state is not acceptable anywhere** — a
create verb that is handed a state it will not honour rejects the call.
