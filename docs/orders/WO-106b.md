# WO-106b — Close the `publish_artifact` file-read surface

status: written, pre-build read pending — do not cut until the read record is appended
assignee: builder
depends: WO-105, WO-106 — both done, merged
closes: ROADMAP debt #25 (trigger FIRED)

## Objective

An agent that can call `qf_publish_artifact` can currently name **any file on the machine** and have
its contents read and stored permanently in the Kernel. Close that, without changing what the
desktop app or the founder can do.

## In plain terms

`publish_artifact` takes a file path and reads whatever is there. That is correct and necessary for
the app — it writes a report to disk, then publishes it. But WO-105 made this one of 24 tools served
to AI agents, and nothing checks *which* path an agent asks for. Measured with a canary file: an
absolute path outside anything the app uses was **accepted, read, hashed, and stored**.

After this order, an agent can only publish files it staged in a designated folder. **The app is
unchanged. The founder's file-picker is unchanged.**

**If it goes wrong:** either the founder's "publish a file" button breaks (it opens a native dialog
and passes an arbitrary path, by design), or the app's own two publish paths break, or the check
lands somewhere an agent can route around.

## RULING — where the constraint lives (architect, final)

**Ruled: the constraint is enforced at the MCP action-serving boundary, not inside the Kernel.**

The original D6 said the rejection must be the Kernel's "so it applies to every caller." **That was
wrong, and it is why this order exists separately.** Measured — there are four caller classes, and
three of them are legitimate:

| Caller | Path source | Legitimate? |
|---|---|---|
| `collab-electron/src/main/agent-host.ts:639` | `$HOME/.collaborator/agent-artifacts/<session>.md`, written moments before | yes |
| `collab-electron/src/main/a2a-bus.ts:68` | `join(COLLAB_DIR, "a2a")`, written moments before | yes |
| `collab-electron/src/windows/shell/src/renderer.js:962` | **native `openFileDialog()` — a human picks any file** | yes |
| **any MCP client** | any string it invents | **no — this is the hole** |

A Kernel-wide path restriction breaks row 3: the founder choosing a file from anywhere on disk is the
feature. So the boundary is not "the Kernel" — it is **"the untrusted caller,"** and untrusted callers
arrive through exactly one door: `registerActionTools` in `tools/qf-read-tools/src/register.ts`.

**Why this is not weaker than a Kernel check.** The threat is *an agent naming a path.* Agents reach
the Kernel only through the served plane. In-process callers are the app itself and the founder's own
dialog, both already inside the trust boundary. A second rogue server iterating `schema.actions` could
bypass this — that is the same residual already logged as **debt #22 (caller identity)**, unchanged by
this order and not its job.

**Fail closed.** A server that serves action tools without an artifact root configured must **refuse
to serve `publish_artifact` at all**, rather than serving it unconstrained. A missing configuration
must never silently mean "allow everything."

**`bytes` is out of scope and unchanged.** The original D6 claimed the app relies on `bytes`; measured,
it does not — the only `bytes` producers are `tools/qf-peer-bus/src/bus.ts:116-125` and
`packages/qf-kernel/src/kernel.test.ts`. `bytes` also cannot cross JSON, as the schema's own field
description states, so it is not an agent-reachable route. Leave it alone.

## Deliverables

**D1 — an artifact root, declared and required.** The action-serving layer takes an artifact root
(configuration, not a hardcoded literal — an env var read once at startup is acceptable and matches
`QF_KERNEL_DB`). If it is absent, `publish_artifact` is **not registered at all** and the served
action count drops by one; the server logs why. Absence must never mean "unconstrained."

**D2 — the check.** Before `execute()` is called for `publish_artifact`, a supplied `path` is
resolved to a real absolute path and rejected unless it is inside the root. The check must survive:
relative paths, `..` traversal, and **symlinks that resolve outside the root** (resolve, then compare
— a string prefix test on the unresolved path is not sufficient and will be baited). Rejection
returns a Kernel-style error over the transport and **writes no row and no event**.

**D3 — nothing else moves.** `packages/qf-kernel` is untouched. `resolveBytes` is untouched. The app's
two callsites, the founder's picker, `qf-peer-bus`, and the Kernel tests all keep working unchanged.
The served tool's advertised schema still lists `path` (WO-106's `tool-discovery` gate will redden if
the advertisement drifts).

## Acceptance gates

Every gate ships with a **bait transcript**: break it, show red, restore, show green. Falsify by
editing shipping code, not a fixture switch — the standard WO-106 set.

**G1 — the hole is closed.** Through the **served** `qf_publish_artifact` tool, a path outside the
root is rejected, with **zero new rows and zero new events** (count both before and after).
*Baits:* (a) an absolute path outside the root — use a canary file, **never a real secret** — must be
rejected; (b) a `..` traversal that normalises outside the root must be rejected; (c) a **symlink
inside the root pointing outside it** must be rejected — this bait exists specifically to kill a
string-prefix implementation; (d) remove the check and confirm (a) goes green, proving the gate is
what stops it.

**G2 — legitimate publishing still works.** A path *inside* the root publishes successfully through
the served tool, and the resulting artifact's `content_hash` matches the file's bytes.

**G3 — fail closed.** With no artifact root configured, `qf_publish_artifact` is **absent** from
`tools/list` and the served action count is 23, not 24. It is never served unconstrained.
*Bait:* make the missing root default to "/" or to allow-all → gate red.

**G4 — the trusted callers are untouched.** `agent-path` and `dock-registry` still pass (both publish
via `path` in-process), and `packages/qf-kernel` has no diff in this rung.

**G5 — full cold suite.** `bun qa/run.ts --all` in a worktree with **zero `node_modules`**, unpiped,
`$?` on its own line, **with no other agent running on the machine**. `golden/` regenerates with no
further diff. Pre-install before any before/after measurement (`agent-path`, debt #23).
