# WO-107 — One real Bovada football capture

status: **open — current**
assignee: —
depends: WO-102 + WO-103 + WO-107b + WO-107c
blocks: WO-109 (the collaborative lower loop over real evidence)

## Objective

Capture one public Bovada NFL response, preserve its bytes as immutable evidence, and load one
future event's open pre-game moneyline instrument and quote through the trusted Kernel pipeline.
Then prove a real Dock seat can discover the complete graph through generated reads and inspect the
quoted prices in the referenced immutable Artifact.

## In plain terms

Put one real Bovada football game and its current win prices into QuantFlow so an agent can inspect
where the data came from, without giving any agent or application path the ability to place a bet.

**If it goes wrong:** QuantFlow invents provider identities, loses the source bytes, duplicates a
snapshot on retry, leaves partial rows after failure, stores a cookie, or demonstrates a model that
answered from prompt text instead of Kernel evidence.

## Measurements that bind this order

Measured 2026-08-01 against the public unauthenticated endpoint, after WO-107c independently passed:

- `GET https://www.bovada.lv/services/sports/event/v2/events/A/description/football/nfl` returned
  HTTP 200 and `application/json` without a request cookie or authorization header;
- the response was 626,056 bytes, SHA-256
  `87874fb418fa1b8ed7ddee3805d0aaa1836a80d146c5542de04254569826795f`, with one top-level coupon,
  17 events, and a ten-minute public cache;
- coupon `path` identifies sport `Football` (`FOOT`) and league `NFL` (`competitionId: "241"`);
- event `25568702` carried `startTime: 1788999600000`, `live: false`, `status: "U"`, two stable
  competitor IDs, and `Game Lines → Moneyline` market `496075087`;
- that market carried `period: {id:"119", description:"Game", live:false, main:true}`, `status:"O"`,
  and two open outcomes with stable IDs and American, decimal, and fractional prices;
- the server set a response cookie even though none was sent. It is not source evidence and must
  never be stored, replayed, logged, templated, or committed;
- there is no production Bovada adapter, capture scheduler, or vendor parser in the repo or research
  vault. The existing seams are `resolveKernelPath`, `resolveArtifactRoot`, `publish_artifact`,
  trusted `register_venue` / `schedule_market_event`, hidden `ingest_market_batch`, and generated
  reads;
- the source body can change at any time. A deterministic fixture proves parsing and failure
  behavior; one bounded live receipt proves the adapter still matches reality. CI must not depend on
  vendor availability.

This endpoint is an observed public website surface, not a contracted API. Any redirect away from
the exact Bovada host, authentication challenge, non-JSON response, incompatible shape, or missing
open moneyline fails closed; do not evade it with browser state or a third-party odds service.

## RULING 1 — one narrow operator path in the shipped app

Add `tools/qf-bovada-football` as a TypeScript library imported by the Electron main bundle. Extend
the already-shipped `qf-canvas` CLI with exactly two operator commands:

```text
qf-canvas market bovada-football --once
qf-canvas market bovada-football --at <ISO-8601 UTC timestamp>
```

The CLI sends one fixed JSON-RPC method to the already-running packaged app. The Electron main
process uses its already-open Kernel and Artifact root, runs once, and returns one bounded receipt.
`--once` starts immediately. `--at` owns one in-memory main-process timer, runs once, and resolves the
RPC call; it rejects a non-UTC timestamp and a target beyond 24 hours. App shutdown cancels the
request/timer. No independent executable, Bun runtime, shell shim, sidecar, SDK, ACP/MCP agent,
child process, recurring loop, cron, systemd unit, Dock command, durable scheduler file, second
socket, or second SQLite database is allowed.

The URL is a package constant. The request uses built-in `fetch`, one `AbortSignal.timeout` no
longer than 20 seconds, `GET`, a fixed non-secret user agent, and `Accept: application/json`. Do not
accept a caller URL, headers, cookies, tokens, proxy, browser profile, or credential-shaped env var.
Follow redirects only while the final origin is exactly `https://www.bovada.lv`; otherwise reject.

Export the parser and dependency-injected finite runner for tests. Electron supplies its existing
`KernelDb`, execute/read helpers, Artifact root, clock, timer, abort signal, and transport; the
package does not open another database or invent another root. The RPC method is a fixed operator
trigger, not a generic command envelope. Do not export a second write handler: product writes remain
calls to `execute()`.

## RULING 2 — source bytes land before market truth

Read the response body stream once as bytes and abort as soon as it exceeds 5 MiB. Reject non-200,
non-`application/json`, invalid JSON, or schema mismatch without any Kernel market write.

Compute the existing Kernel `contentHash(bytes)`, then durably publish the exact JSON body beneath
the resolved `QF_ARTIFACT_ROOT`. The final path is deterministic from the hash. Stage under that same
root, fsync/close, create the final path exclusively (or byte-verify an existing same-hash file), and
only then call:

```text
publish_artifact {
  kind: "result_set",
  content_hash: <body SHA-256>,
  storage_ref: <absolute durable path>,
  bytes: <exact response bytes>
}
```

No response header is part of the Artifact. In particular, never preserve `set-cookie`. Remove only
the runner-owned staging file in `finally`. If this invocation created the final file and
`publish_artifact` rejects, read the Kernel: delete that final file only when no Artifact row owns
it; otherwise retain it. Never delete an existing file, durable Artifact, or operator data.

One Artifact is allowed to remain when later parsing/context/ingest fails. That is honest captured
evidence, not partial market truth, and the same bytes must be replayable without a network retry.
The three Kernel commands are separate commit boundaries: a registered Venue or scheduled Event may
also remain if its own command succeeded before a later failure. Those rows are provenance-backed
context, not residue. Retry must read-classify and reuse that honest prefix; only the atomic market
batch promises zero Instrument/Quote/link residue on its own failure.

## RULING 3 — select exactly one honest moneyline

From the response, select the earliest event satisfying every predicate:

```text
sport == "FOOT"
live == false
status == "U"
startTime is a finite millisecond timestamp later than observed_at
competitionId matches coupon path type LEAGUE with description "NFL"
exactly two competitors with distinct non-empty ids/names and one home=true, one home=false
display group description == "Game Lines"
market description == "Moneyline", status == "O"
period.description == "Game", period.live == false, period.main == true
exactly two outcomes, each status == "O", type in {"H","A"}, with distinct ids and prices
```

Sort eligible events by `startTime`, then numeric/string event ID as a stable tie-break. Reject zero
or ambiguous matching Game-Line moneyline markets. Preserve provider strings; do not infer a game
from team names or synthesize an identity when an ID is absent.

The committed parser fixture is a minimal, sanitized excerpt of the measured public response with
one qualifying event plus bounded decoys. It contains no cookie, account data, ticket, stake, or
operator data. The live response itself is not committed.

## RULING 4 — exact Kernel mapping

Let `A` be the Artifact/body hash. After `publish_artifact`, read `T` from the returned Artifact
state's durable `created_at`; do not use a fresh wall clock for downstream provenance. Use one
deterministic trace root, `bovada:nfl:` + `A`; command span IDs are stable suffixes under that trace.
A later response with a byte-identical body returns the same Artifact and therefore the same `T`,
then content-dedupes to the existing Quote rather than inventing a new observation timestamp.

```text
register_venue {
  venue_id: "venue-bovada",
  kind: "sportsbook",
  name: "Bovada",
  source_artifact_id: A,
  observed_at: T
}

schedule_market_event {
  market_event_id: "bovada:event:" + event.id,
  sport: "football",
  starts_at: new Date(event.startTime).toISOString(),
  competition: "NFL",
  source_artifact_id: A,
  observed_at: T
}

ingest_market_batch {
  source_artifact_id: A,
  observed_at: T,
  venue_id: "venue-bovada",
  instruments: [{
    id: "bovada:instrument:" + event.id + ":" + market.id,
    market_event_id: "bovada:event:" + event.id,
    kind: "moneyline",
    params: {
      provider: "bovada",
      competition_id: event.competitionId,
      provider_event_id: event.id,
      provider_market_id: market.id,
      period_id: market.period.id,
      period: market.period.description
    },
    sides: [away outcome description, home outcome description],
    correlation_group: "bovada:event:" + event.id + ":moneyline"
  }],
  quotes: [{
    id: "bovada:quote:" + event.id + ":" + market.id + ":" + A,
    instrument_id: matching instrument id,
    book: "bovada",
    data_ref: A,
    coverage: {
      observed_at: T,
      event_id: event.id,
      market_id: market.id,
      outcome_count: 2,
      price_formats: ["american", "decimal", "fractional"]
    }
  }]
}
```

`coverage` is only that sufficiency summary. Outcome IDs, names, and prices remain in Artifact bytes;
copying them into `coverage` would turn an open JSON hint into a second quote store. Do not create
competitors in this order: WO-107c has no trusted competitor command and the SCOPES gate requires
the venue/event/instrument/quote graph, not fabricated roster rows.

The existing Kernel transaction derives `lists`, `offered_on`, and `quotes`. The adapter never writes
SQL and never exposes the three trusted market actions through MCP.

## RULING 5 — classify existing truth before writing

New source bytes are not an exact replay of context rows created from an older Artifact. Calling
`register_venue`, `schedule_market_event`, or re-submitting an existing instrument with new `A`/`T`
would correctly raise the WO-107c provenance conflict. The runner must therefore read and classify
Kernel state before choosing commands:

- missing `venue-bovada` → call `register_venue`; matching `{kind:"sportsbook", name:"Bovada"}` →
  reuse it without a command; any mismatch → fail closed;
- missing event → call `schedule_market_event`; an exact matching `scheduled` event → reuse it
  without a command; any field/status mismatch → fail closed;
- missing instrument → include it in `ingest_market_batch`; an exact matching instrument with the
  one expected `lists` and `offered_on` edge → omit it from the batch; any field/edge mismatch → fail;
- missing quote ID for `A` → ingest that quote, either beside a new instrument or as a quote-only
  batch referencing the existing instrument; an exact matching quote and `quotes` edge → return
  content-deduped with zero writes; any mismatch → fail.

Use existing `getObject` / `getLinks` readers and `execute()` only. Reads may classify truth; they do
not authorize direct SQL writes. This produces three honest cases: first capture creates the graph;
same-body capture writes nothing; changed-body capture of the same provider market adds one Artifact,
one Quote, one `quotes` edge, and their two events while reusing—not replaying—stable context.

### D5 — real data and real seat evidence

> Which scheduled NFL event did Bovada publish, which moneyline instrument is offered on it, and

## Required falsification

Five baits, each red → exact restore → green:

1. Permit a caller URL/header or accept a final non-Bovada origin.
2. Publish market context before the durable Artifact rename, or include a response `set-cookie` in
   stored bytes/metadata.
3. Remove one strict selector predicate so an in-play, non-main-period, closed, or ambiguous market
   is accepted.
4. Reissue context/an existing instrument with changed source provenance instead of read-classifying
   it, or commit before the final derived link.
5. Remove app timer/request/staging cleanup, drop the shipped CLI/RPC path, or serve a trusted
   market action to the seat.
