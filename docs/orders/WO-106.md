# WO-106 — The cold seat, and retirement (doctrine P3, rung 3 of 3)

status: open, cuttable — pre-build read run 2026-07-26 (`grok-4.5-high`), **thirteen findings,
seven High, all fixed in this text**; record appended at the bottom
assignee: builder
depends: WO-104 (served read plane), WO-105 (action tools + GATE 1/GATE 2) — both done, merged

## Objective

The generated tool plane becomes **self-describing** — an agent that has never been told about
QuantFlow can list the tools and see exactly how to call them — and the hand-written read verbs it
replaces are deleted, so there is one way to read the ontology instead of two.

## In plain terms

WO-105 gave agent seats 24 write tools and 69 read tools. The read tools already describe
themselves. **The 24 write tools do not:** an agent asking "what can I do?" sees names with no
arguments, so it cannot call them without being told the shape out of band. This order makes the
write catalogue self-describing, then deletes the four hand-written read functions the generated
ones replace.

**If it goes wrong:** either the advertised shape becomes a second hand-maintained copy that drifts
from the schema (the second-truth-store failure), or MCP starts validating and quietly becomes a
second gate in front of the Kernel (which WO-105 was written to prevent), or the deletions silently
change app behaviour — the boot path reads fewer rows than before and every gate stays green.

## RULING 1 — how discovery is fixed (architect, final; ROADMAP debt #24)

**Ruled: the served `tools/list` response is emitted by a low-level request handler carrying the
real generated JSON Schema, while the action tools' `registerTool` validator stays permissive so
`execute()` remains the only layer that rejects an action's input.**

This is not a design sketch. It was **probed end-to-end before this order was written**, against
`@modelcontextprotocol/sdk@1.29.0`, with an `InMemoryTransport` client/server pair:

```
override handler ran : true
advertised props     : ["kind","stake"]
advertised required  : ["kind","stake"]
callTool passthrough : "{\"anything\":1,\"kind\":\"single\"}"
```

Read the last line carefully: a bogus `anything` key **reached the handler untouched** — the SDK
neither stripped nor rejected it. That is the property this rung depends on. `McpServer` exposes the
underlying server (`readonly server: Server`, `mcp.d.ts:18`), Protocol exposes `setRequestHandler`
(`protocol.d.ts:389`), and `ListToolsRequestSchema` is exported from `types.js`.

**Scope of "sole rejecting layer" — narrowed at the pre-build read.** This claim applies to **action
tools only**. Read tools already pass real Zod shapes to `registerTool` and MCP already validates
them; that is correct and **stays unchanged**. Reads are lookups with one declared id or filter set;
writes are the path GATE 1 guards. Do not make read tools permissive "for consistency."

**Why the obvious alternative is forbidden.** Passing the real Zod schema to `registerTool` for
actions would also fix the advertisement — and would make the SDK reject malformed calls *before*
`execute()` sees them, masking GATE 1 and reintroducing the "two validators" shape WO-105's D3
forbade. Do not do it. For actions, the advertisement and the validator are deliberately different
objects.

**One meaning, mandatory:** the handler's response is produced by calling the **generator at
runtime** (`generateMcp(schema)` or its equivalent entry point) — **not** by reading
`golden/tools.json`, and not from any hand-written literal. Golden is a committed artefact that can
be stale mid-edit; the live schema cannot. A hand-written advertisement is a second truth store
about the schema, which is the One Rule violation this repo exists to prevent.

**`operatorOnly` still governs.** The advertisement lists exactly the served set. `qf_observe_ticket`
is generated into `golden/tools.json` and **must not appear in the advertisement**. The founder's
door stays off the map; this rung must not widen it.

## RULING 2 — what "the cold seat" can honestly prove (architect, final)

`SCOPES.md` states this rung's gate as: *"The cold seat finishes the task through generated tools
only, with no prompt naming a tool."* **Measured before writing this order: that cannot be a gate,
and attempting it would produce a forged assertion.**

Every agent seat in this repo runs `MockLanguageModelV3` from `ai/test`
(`tools/runtime-proof/agent-package/src/acp-main.ts:20,32`;
`species/critic-mock/agent-package/src/acp-main.ts:20,32`) — deliberately, so gates need no API
keys. **A mock model does not choose tools; it replays a script.** Scripting a mock to call
`qf_create_ticket` *is* priming, by construction. A gate built that way would display discovery and
prove replay: the WO-004 forged-assertion class, which this repo has already paid for twice.

A real-model gate is also ruled out, for two independent reasons: the **cold-state rule** says a gate
installs whatever it needs, and a gate cannot install an API key; and a nondeterministic gate that
fails for reasons unrelated to the thing it guards trains people to discount it — the exact harm
logged as debt #23.

**So the claim splits in two, and both halves ship:**

**(a) The machine half — sufficiency, as a permanent gate.** Assert that everything required to call
every served tool is present in `tools/list` alone. This is deterministic, cold-runnable, and
falsifiable. **It proves the surface is sufficient for discovery. It does not claim a model
discovered anything, and no report may describe it as if it did.**

**(b) The human half — one founder-witnessed demo, as evidence, explicitly not a gate.** A real
model, prompted with a task and **no tool named**, completing it through the served plane.
Transcript archived under `docs/orders/evidence/wo-106/`, labelled a demo, with its non-determinism
stated. No gate depends on it.

**`SCOPES.md` must be amended by this order** (D0) to carry the split wording. The contract text
currently promises something unprovable; leaving it hands the next pre-build reader a contradiction —
the failure shape WO-105's read caught as its finding 8.

## RULING 3 — the deletions are not a clean swap (architect, final)

Measured: **three of the four retirement targets differ behaviourally from their generated
replacements**, and two differences are silent.

| Hand-written | Generated replacement | Difference — measured |
|---|---|---|
| `listAgentDefinitions` (`db.ts:102`) — `ORDER BY created_at ASC` | `queryObjects` (`read.ts:81`) — hardcoded `ORDER BY created_at DESC` | **Species registry order reverses** |
| `listArtifacts` (`db.ts:88`), `listAgentSessions` (`db.ts:95`) — **no LIMIT** | `queryObjects` — `limit = 100` default | **Silently caps at 100 rows** |
| `getAgentDefinition` (`db.ts:109`) | `getObject` (`read.ts:64`) | Clean swap — `id = name`, both return row-or-null |

The limit difference lands in `reconcileStaleSessions()` (`agent-host.ts:263`) — **the same boot
function WO-105's blocker was in.** With more than 100 stale sessions, boot reconciliation would
silently leave some open and every gate would stay green.

**Ruled, with the API named** (the pre-build read found three competing spellings, all satisfying an
earlier draft):

- `queryObjects` gains `order?: "asc" | "desc"`, defaulting to `"desc"` so today's behaviour is
  unchanged for every existing caller.
- Unbounded reads are expressed as **`limit?: number | null`**, where `null` means no `LIMIT` clause
  is emitted. Not `0` (the generated schema carries `exclusiveMinimum: 0`, so `0` is illegal),
  not `Infinity`, not omission — omission keeps the documented default of 100.
- Every migrated caller passes what it actually needs rather than inheriting a default. A caller that
  previously read every row must still read every row. **No caller may silently truncate**, and the
  boot path's behaviour above 100 rows is gated (G5).

Adding these parameters is in scope precisely because deleting the hand-written verbs forces it.

## Deliverables

**D0 — `SCOPES.md` amended, in its own commit, first.** Rewrite WO-106's gate line to the split
wording from Ruling 2, and soften the retirement paragraph's "four wrappers" to match the corrected
census. No code in this commit.

**D1 — the advertisement becomes honest.** `tools/list` is served from
`setRequestHandler(ListToolsRequestSchema, …)` on the underlying server, emitting the real generated
JSON Schema for **every served tool** (reads included — no special-casing), produced by calling the
generator at runtime. The action tools' `actionTransportInput` stays permissive; read tools' Zod
validation stays as-is. `_meta["qf/inputSchema"]` becomes redundant — remove it rather than leave two
copies.

**D2 — `queryObjects` gains `order` and nullable `limit`.** Exactly as spelled in Ruling 3. The
generated `_query` tool's advertised schema will change as a result; that is intended, and D1's gate
checks it. **`golden/` therefore changes in this rung** — see G6, which does not require golden to
match today's committed bytes.

**D3 — the hand-written verbs are deleted and every consumer migrated.** Delete `listArtifacts`,
`listAgentSessions`, `listAgentDefinitions`, `getAgentDefinition` from `packages/qf-kernel/src/db.ts`,
their re-exports from `index.ts` and `portable.ts`, and the **five** wrappers in
`collab-electron/src/main/kernel.ts`. Migrate every consumer — app, kernel, and **QA gates** — to
`getObject` / `queryObjects` with explicit `order` and `limit`. `created_at ASC` is preserved where it
exists today; the boot path and `kernel.ts:60` read every row (`limit: null`). No alias, wrapper, or
re-export may survive that wraps the same hand-written SQL under a new name.

**D4 — the sufficiency gate `tool-discovery`.** Asserts, against the live served plane, that:
every served tool has a non-empty description; **every** advertised `inputSchema` deep-equals the
generator's output for that tool (see G1 for the single equality bar); the advertised name set equals
the live served set and excludes every `operatorOnly` action; and **for the named task below**, every
required field is reachable from the advertisement alone.

**The named task, so two builders cannot pick different ones:** *create a run, start it, publish an
artifact linked to it, then read that artifact back.* It spans creation, transition, a link, and a
read — the four shapes the plane must support — and every field it needs must be discoverable from
`tools/list` with no other source.

Register it as gate `tool-discovery`. The gate count is **derived from the runner's own registry, not
asserted as a literal** — a hardcoded `16` is the failure class G3 and D1 exist to prevent.

**D5 — the founder demo, as evidence.** One real-model run, no tool named in the prompt, completing
the D4 task through the served plane. Transcript plus a plain-language note on what it does and does
not prove, under `docs/orders/evidence/wo-106/`. **No gate depends on this.** If no real model is
available in the builder's environment, **report D5 as not run and continue with D0–D4** — do not
simulate it, do not substitute a mock and call it a demo, and **do not stop the order.**

**D6 — close the `publish_artifact` file-read surface (ROADMAP debt #25, trigger FIRED).**

Added after WO-105 merged, when a post-merge review found it and the checking seat confirmed it with
a canary file: `resolveBytes` (`create.ts:30-36`) does `readFileSync(input.path)` on **any** string
path, and WO-105 made `qf_publish_artifact` one of 24 served action tools. Measured — an arbitrary
absolute path was **accepted, read, and stored** as a durable content-addressed artifact. Neither the
builder nor the pre-build read caught it because neither half is a defect alone: D0 declaring `path`
was correct, and D3 serving the action was correct. The composition is the hole.

Constrain `path` to a declared staging root. Reject absolute paths outside it, reject `..` traversal
after normalisation, and reject symlinks that escape it. **The in-process `bytes` route is unaffected
and must keep working** — the Electron app publishes through it. The rejection is the Kernel's, at or
before `resolveBytes`, so it applies to every caller rather than only to MCP.

This is in scope for this rung because this rung owns the serving surface, and because WO-107 brings
external market data — shipping that with an open file-read primitive is not acceptable.

## Acceptance gates

Every gate ships with a **bait transcript**: break it, show red, restore, show green. A gate that has
only ever been green is decoration.

**G1 — the advertisement is real, complete, and derived.** For **every** served tool, the advertised
`inputSchema` deep-equals the generator's output for that tool — the whole object, not a subset of
keys, and not a property count. **This is the single equality bar; D4 references it rather than
restating a weaker one.**
*Baits, all three required:* (a) hand-edit one advertised property → red, and the failure must name
the offending tool (proves per-tool comparison, not a canary); (b) point the server at the fixture
schema and confirm the advertised set follows it → proves derivation rather than a frozen snapshot;
(c) add a property to a real schema action, regenerate, and confirm the advertisement changes with
**no gate edit** → proves the derivation is live.
*Explicitly closed:* an implementation that answers `tools/list` from a snapshot taken once from
`golden/tools.json` fails bait (b), and an implementation that deep-equals only one canary tool fails
bait (a).

**G2 — MCP is still not a validator for actions.** Through a served action tool, a call carrying an
unknown key reaches `execute()` and is rejected **by the Kernel**. The gate asserts three things, not
one: the error is the Kernel's strict-parse rejection (naming the unrecognized key — not merely
`isError: true`), **zero new rows**, and **the event count is unchanged before and after**.
*Bait:* swap `actionTransportInput` for the real schema → the rejection becomes the SDK's, the
Kernel's error text disappears, gate red. This gate is what keeps Ruling 1 honest.

**G3 — the operator's door is still absent.** Expressed as **set relations**, re-enumerated live on
every run: the advertised set equals the served set; the served set equals
`{generated tools} minus {operatorOnly actions}`; and `qf_observe_ticket` is in the generated set and
in neither of the other two. *Today those sets measure 93 / 93 / 94 — that is a measurement, not the
assertion.* Hardcoding the numbers is a defect: an implementation that compares against stored arrays
rather than re-enumerating fails the bait.
*Bait:* remove `operatorOnly` from `observe_ticket` → red on all three relations.

**G4 — the verbs are gone, including under new names.** No **declaration** of `listArtifacts`,
`listAgentSessions`, `listAgentDefinitions`, or `getAgentDefinition` remains in
`packages/qf-kernel/src` or `collab-electron/src/main`, and no re-export or alias re-exposes the
deleted SQL under a different name. Scope is **declaration and export sites** — `export function`,
`export {`, and import lists — **not** every occurrence of the string. The renderer IPC method name
`window.api.qf.listArtifacts` is explicitly exempt and must still exist (see census note); a gate
that reddens on it is mis-scoped.
*Baits:* (a) reintroduce one wrapper → red; (b) reintroduce the same SQL as `listAllArtifacts` and
re-export it → red, proving the gate catches renaming, not just the old spelling.

**G5 — the boot path did not silently shrink.** Seed **more than 100** `agent_session` rows **in
statuses `reconcileStaleSessions` actually acts on** (`starting`, `running`, `blocked`, plus the
`cancelled`/`failed` branch), run the boot reconciliation path, and assert every one is closed.
The post-condition is counted by an **independent unbounded query**, never by reusing the same call
the boot path makes.
*Bait:* restore `limit` to its default on that call → red, with rows left open.
*Explicitly closed:* seeding 101 rows of which ≤100 are in acted-on statuses does not satisfy this
gate; the acted-on count must itself exceed 100.

**G6 — full cold suite.** `bun qa/run.ts --all` in a worktree with **zero `node_modules`**, unpiped,
`$?` on its own line. Exit 0, and the gate list includes `tool-discovery`.
**On `golden/`:** this rung changes it deliberately (D2 adds `order` and nullable `limit` to the query
tools). The requirement is **determinism, not stasis** — after the intended regeneration is committed,
`bun run generate` must produce **no further diff**. Do not read this clause as "golden matches
today's committed bytes"; the first draft did, and it contradicted D2.
Pre-install before any before/after measurement — `agent-path` gives a false FAIL in a sandboxed
shell (debt #23). Never pipe the runner.

**G7 — the file-read surface is closed.** `publish_artifact` with a path outside the declared
staging root is **rejected by the Kernel**, writing no row and no event; a path inside it still
works; and the in-process `bytes` route still works.
*Baits:* (a) an absolute path to a file outside the root (use a canary file, never a real secret) →
rejected, zero rows, zero events; (b) a `..` traversal that normalises outside the root → rejected;
(c) remove the check → both baits go green, proving the gate is what stops them.
